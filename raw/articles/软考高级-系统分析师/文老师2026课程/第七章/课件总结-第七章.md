## 一、软件工程基础概念

1. **软件工程定义**：应用计算机科学、数学、管理科学原理，用工程化原则方法解决软件问题；目标：**提高软件生产率、提升软件质量、降低软件成本**。
2. **软件工程三要素**：**方法、工具、过程**。
3. **软件生命周期（生存周期）**：软件产品从概念形成，经过开发、使用维护，直到退役的完整全过程。

### 软件生命周期 3 大类过程

1. **基本过程**：获取、供应、开发、运作、维护。
    
    - 开发过程：需求分析、设计、编码、集成、测试、安装验收。
    - 维护过程：软件迁移、退役。
    
2. **支持过程**：文档、配置管理、质量保证、联合评审、审核、问题解决、易用性过程。
3. **组织过程**：管理、基础设施、改进、人力资源、资产管理、重用大纲管理、领域工程过程，用于持续优化组织级软件过程。

## 二、软件过程管理

### 1、CMM & CMMI

- CMM：软件能力成熟度模型；CMMI 是多学科综合改进框架，不止软件领域，提升过程质量与效率。
    
    **CMMI 能力等级表**
    
    | 能力等级 | 特点 | 关键过程区域 |
    
    | ---- | ---- | ---- |
    
    | 初始级 | 过程不可预测、缺少控制 | 无 |
    
    | 已管理级 | 过程服务于项目 | 需求管理、项目计划、配置管理、项目监督与控制、供应商合同管理、度量和分析、过程和产品质量保证 |
    
    | 已定义级 | 过程服务于整个组织 | 需求开发、技术解决方案、产品集成、验证、确认、组织级过程焦点、组织级过程定义、组织级培训、集成项目管理、风险管理、集成化的团队、决策分析和解决方案、组织级集成环境 |
    
    | 定量管理级 | 过程可度量、可量化控制 | 组织过程性能、定量项目管理 |
    
    | 优化级 | 聚焦持续过程改进优化 | 组织级改革与实施、因果分析和解决方案 |

## 三、软件过程模型

### 1. 瀑布模型（SDLC 软件开发生命周期）

![[Image 18.jpg|image]]

瀑布模型示意图

阶段划分：**定义阶段（可行性分析 / 计划、需求分析）；开发阶段（设计、编码、测试）；维护阶段（运行维护）**

- 特点：线性顺序，阶段确认后进入下一阶段，不通过则返回前面阶段；适合**需求明确、变更少**项目；尽量减少阶段反复。

### 2. 螺旋模型

![[Image 19.jpg|image]]

螺旋模型示意图

> 结合瀑布模型线性控制 + 原型迭代演化；软件开发是增量发布；一圈代表一次迭代周期。
> 
> 每个周期 4 个象限（4 阶段）：**制订计划 → 风险分析 → 实施工程 → 客户评估**

- 核心：**强调风险分析**；适合庞大复杂、高风险大型系统。

### 3.V 模型

![[Image 20.jpg|image]]

V模型示意图

V 字左右两边一一对应：

- 左侧（开发）：用户需求→需求分析→概要设计→详细设计→编码实现
- 右侧（测试）：验收测试 ↔系统测试 ↔集成测试 ↔单元测试

> 对应关系：编码对应单元测试；详细设计对应集成测试；概要设计对应系统测试；需求分析 / 用户需求对应验收测试。
> 
> 特点：测试与开发阶段绑定；缺点：早期错误不能及时发现。

### 4. 原型化模型

![[Image 21.jpg|image]]

原型化模型流程图

流程：确定用户基本需求 →设计初始原型 →试用评价原型 →不满意则修改完善原型；满意则整理原型输出文档。

- 核心：快速构造原型，和用户交互，挖掘不清楚的需求。
- 原型分类
    
    ①按实现功能：水平原型（仅导航演示）、垂直原型（实现部分真实功能）
    
    ②按最终结果：抛弃式原型、演化式原型

> 适用场景：**需求模糊、很难一次性明确需求**；原型法更多是开发思想，不是完整独立方法论，需要和别的方法组合使用。

### 5. 增量模型

![[Image 22.jpg|image]]

增量模型示意图

思路：优先开发核心模块，分多个增量；每个增量完整执行：分析→设计→编码→测试，交付给客户；逐步叠加全部功能。

- 特点：每个增量版本是可独立运行产品；难点：需求划分成多个增量；缺点：缺少全局规划，模块划分困难。

### 6. 喷泉模型

面向对象驱动，以用户需求为动力；具备**迭代性、无间隙性**；阶段之间没有明显界限，适合面向对象开发。

### 7. 基于构件开发 CBSD

复用构件库构件（组织自研构件或者外购成品构件）；提高可靠性、节省成本时间，强化复用。

### 8. 形式化方法模型

基于严格数学基础；产出软件形式化数学规格说明。

### 9.RAD 快速应用开发

瀑布高速变种，基于构件快速开发；分为业务建模、数据建模、过程建模、应用生成、测试切换。依赖大量复用构件。

### 10. 敏捷开发模型

![[Image 23.jpg|image]]

敏捷开发总览图

**敏捷开发宣言 4 大价值观**

1. 个体和交互 胜过 过程和工具

2. 可以工作的软件 胜过 面面俱到的文档

3. 客户合作 胜过 合同谈判

4. 响应变化 胜过 遵循计划

敏捷核心：拥抱变化；迭代增量开发；小版本发布；发挥人的作用；客户深度参与；少文档。

主流敏捷方法：

1. **XP 极限编程**：沟通、简单、反馈、勇气；包含结对编程、测试先行、重构等 12 个最佳实践。
2. DSDM 动态系统开发：80/20 原则，用户参与，变更可逆，频繁交付。
3. **Scrum**：迭代周期 Sprint（2‑4 周）；自组织团队，按需求优先级实现增量产品。

### 11.RUP 统一软件过程

RUP 四大阶段：

1. **初始阶段**：确立项目边界，识别外部交互实体，评估业务风险，做项目计划。
2. **细化阶段**：分析业务，建立系统架构，消除高风险，搭建开发环境。
3. **构建阶段**：开发全部构件功能，集成，测试，产出可执行版本。
4. **移交阶段**：交付产品给用户，培训用户，收集反馈，调整版本。

## 四、信息系统开发方法

1. **结构化方法（生命周期法 SA‑SD‑SP）**

> 核心：**自顶向下、逐步求精、模块化**

- 优点：阶段划分清晰，文档完整，方便项目管控。
- 缺点：不适应需求频繁变化；侧重功能，较少考虑数据结构。
- 工具：数据流图 DFD、数据字典、结构化语言、判定表、判定树。

2. **面向对象 OO 方法**
    
    一切事物视为对象；分析、设计、实现阶段边界模糊，无缝衔接；
    
    局限：大型项目有局限，不能覆盖前期系统分析之前环节。
    
3. **原型化方法**（见上文过程模型部分）
    
4. **面向服务 SO 方法**
    
    抽象层级递进：面向对象 →基于构件 →面向服务。层次：操作、服务、业务流程；业务流程通过编排调用多个服务完成业务目标。
    

## 五、软件开发环境与工具 SDE / CASE

1. **软件开发环境集成机制三部分**
    
    ①**数据集成**：信息库，存储系统开发信息、环境支撑信息，实现信息共享；
    
    ②**控制集成**：工具间通信协同，调度组合工具；
    
    ③**界面集成**：统一风格用户界面。
    
    ICASE：集成 CASE 环境。
    
2. **软件工具三大类**
    
    1）**软件开发工具**：需求、设计、编码排错工具
    
    2）**软件维护工具**：版本控制、文档分析、逆向工程、再工程工具
    
    3）**软件管理 & 支持工具**：项目管理、配置管理、软件评价工具
    

> 工具选择取决于：最终用户、开发人员。

## 六、软件重用和再工程

1. **软件重用**：多次复用相同 / 相似软件元素；粒度越大构件越大。
    
    三层重用：知识重用；方法标准重用；软件成分重用。
    
    构件重用方式：组装、继承、实例化。
    
    **领域工程**：构造可复用构件库，包含领域分析、构件开发。构件分类方式：枚举、刻面、属性‑值分类。

2. 逆向工程、重构、设计恢复、再工程、正向工程

- **逆向工程 Reverse Engineering**：从程序代码恢复高层抽象描述（设计恢复），只分析不修改。
- **再工程 Re‑engineering** = 逆向工程 + 新增需求 + 正向工程；重构现有系统，生成新版本，改善性能、增加新功能。

## 七、软件产品线

![[Image 25.jpg|image]]

软件产品线双工程模型

软件产品线：一组共享通用特征集的产品集合，面向特定业务领域；提升质量、缩短开发周期、降低成本。

两大工程：

1. **领域工程**：面向公共核心资源；领域分析→领域设计→领域实现；产出领域需求模型、领域架构、可复用构件。
2. **应用工程**：面向单个新产品；基于领域工程产出，结合新系统需求做：需求分析→系统设计→系统实现，产出各个新系统。

> 领域工程产出核心资源库，应用工程复用库来开发产品；两者之间存在反馈，新产品会反过来更新核心资源库。

## 八、软件形式化方法

建立严格数学基础，具备精确语义；分广义（全套工程方法）狭义（规格说明与验证）。

### 程序正确性验证

1. **动态方法**：必须运行程序，典型是软件测试；无法覆盖全部输入路径。
2. **静态方法**：不运行程序源码分析；包含静态分析、符号执行、定理证明、模型检测。
    
    - 模型检测难点：需要领域专家建立合适抽象模型。
    

## 九、高频考试真题考点摘录

1. 需求明确、变更少 →**瀑布模型**；大型高风险系统→**螺旋模型**；需求模糊不明确优先**原型法**。
2. 逆向工程：转换到更高抽象；再工程：修改重构得到新版本。
3. 版本控制工具：属于**软件维护工具**；软件评价工具：属于**软件管理支持工具**。
4. RUP4+1 视图记住 5 个视图各自面向的角色。
5. CMMI5 个能力等级从低到高：初始级→已管理级→已定义级→定量管理级→优化级。
