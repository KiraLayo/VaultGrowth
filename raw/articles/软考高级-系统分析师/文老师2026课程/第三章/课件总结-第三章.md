## 一、数据库基础概念与三级模式两层映像

### 1. 核心定义

1. **数据**：描述事物的符号记录，包含文本、图像、音视频、业务档案等。
2. **DB（数据库）**：长期存储、有组织、可共享的数据集；特征：结构化、多用户共享、低冗余、高数据独立性、易扩展。
3. **DBS（数据库系统）**：四大组成：数据库 DB、硬件、软件（OS+DBMS + 应用）、人员（DBA、设计员、程序员、终端用户）。
4. **DBMS（数据库管理系统）**：核心软件，提供数据定义、增删改查、运行管理、存储管理、数据库运维全套能力。

### 2. 三级模式（三层架构）

1. **外模式（视图层）**：面向用户，对应数据库视图；一个数据库可多个外模式，只展示用户需要的数据。
2. **概念模式（模式 / 基本表层）**：全局逻辑结构，对应基础表，完整描述所有实体、关系、属性。
3. **内模式（物理存储层）**：对应磁盘存储文件，描述数据物理存储结构、存取路径。

### 3. 两层映像与数据独立性

1. **外模式 / 概念模式映像 → 逻辑独立性**
    
    基础表（概念层）结构修改时，仅调整此映射，**应用程序无需改动**。
2. **概念模式 / 内模式映像 → 物理独立性**
    
    底层物理存储方式修改时，仅调整此映射，**上层表与程序不受影响**。

## 二、数据库设计全流程

完整设计分 5 阶段，各阶段产出明确：

1. **需求分析**：产出需求说明书、数据流图 DFD、数据字典；明确实体、属性、业务关系。
2. **概念结构设计**：E-R 图建模，抽象现实业务实体与联系。
3. **逻辑结构设计**：E-R 转关系模式，规范化（1NF~4NF），消除冗余依赖。
4. **物理结构设计**：设计磁盘存储结构、索引、分片、存取方法。
5. **数据库实施与运维**：建库、加载数据、测试、优化、备份恢复。

1. **基础术语**
    
    - 实体：客观可区分事物；**弱实体**必须依赖强实体才能存在（如家长依赖学生）。
    - 属性：实体特征；域 = 属性取值范围；主键唯一标识实体。
    - 实体集：同类型实体集合。
    
2. **实体联系类型**
    
    - 二元：1:1、1:N、M:N（多对多必须单独建关系表）；
    - 多元：三个及以上实体可构成 1:n 或 m:n 联系。
    
3. **E-R 转关系规则**
    
    - 1:1：可合并到任意一方表，或单独建表；
    - 1:N：在多方表加入一方主键作为外键；
    - M:N：新建独立关系表，存储双方实体主键，可加联系自身属性。
    

## 三、数据模型分类与三要素

### 1. 主流数据模型

1. **概念模型（E-R）**：用户视角，现实世界→信息世界第一层抽象。
2. **传统逻辑模型**
    
    - 层次模型：树形；网状模型：多对多网状；
    - **关系模型**：二维表格，外键表达实体联系；优点：数学基础严谨、简单透明、独立性高；缺点：查询效率低于非关系模型。
    
3. **面向对象模型**：以对象为单位，包含属性 + 方法，支持类、继承。

### 2. 数据模型三要素

- 数据结构：描述实体、关系存储形式；
- 数据操作：增删改查等允许执行的运算；
- 完整性约束：主键、外键、值域等规则。

## 四、关系代数（含补充课件拓展）

### 1. 基础集合运算（R、S 为同结构关系）

1. **并 ∪**：合并两张表，去重；
2. **交 ∩**：仅保留两张表完全相同元组；
3. **差 −**：保留只在 R 存在、S 没有的元组；
4. **笛卡尔积 ×**：所有元组两两拼接，列数 = R 列数 + S 列数，行数 = R 行数 ×S 行数。

### 2. 专用关系运算

1. **投影 π**：选取指定列（垂直筛选）；
2. **选择 σ**：按条件筛选行（水平筛选）；
3. **连接**
    
    - 等值连接：笛卡尔积后取属性值相等行，保留重复列；
    - 自然连接 ⋈：等值连接基础上**去除重复同名列**；
    - 外连接：左外（保留左表全部元组）、右外（保留右表全部）、全外（两边全部保留，无匹配填充 NULL）。
    
4. **除法 ÷**
    
    核心逻辑：设 R (X,Y)、S (Y)，R÷S 结果为 X 列，**X 的象集包含 S 全部 Y 元组**；常用于 “查询选修了全部课程的学生” 类考题。

### 3. 拓展演算（补充课件新增）

1. **元组演算 {t|P (t)}**：变量为完整元组，用逻辑谓词筛选；
2. **域演算**：变量为单个属性字段；
3. 运算符优先级：比较符 > 非 > 与 > 或，括号最高。

## 五、函数依赖、键、范式（软考重难点）

### 1. 函数依赖基础

- X→Y：给定 X，能唯一确定 Y；
- **部分依赖**：Y 依赖 X 的子集（仅存在于非主键属性）；
- **传递依赖**：X→Y、Y→Z，则 X→Z；
- **多值依赖**：X→→Y，给定 X，一组 Y 值与其他属性无关，4NF 考点。

### 2. 各类键定义

1. 超键：能唯一标识元组的属性组合（可冗余）；
2. 候选键：最小超键，无冗余属性；
3. 主键：人为选定的一个候选键；
4. 外键：引用另一张表主键的属性；
5. 主属性：候选键包含的属性；其余为非主属性。

### 3. 三大完整性约束

1. 实体完整性：主键非空、不重复；
2. 参照完整性：外键值要么匹配主表主键，要么为空；
3. 用户自定义完整性：业务自定义值域约束。

### 4. 范式分层（从低到高）

1. **1NF**：列不可再分，禁止表中嵌套小表；
2. **2NF**：满足 1NF，**消除非主属性对主键的部分函数依赖**；
3. **3NF**：满足 2NF，**消除非主属性对主键的传递依赖**；
4. **BCNF（巴斯 - 科德范式）**：满足 3NF，**每一个函数依赖的决定因素都包含候选键**；仅考虑函数依赖时最高范式；
5. **4NF**：新增内容，消除**非平凡、非函数依赖的多值依赖**；考虑多值依赖时最高范式，实际开发很少用到。

## 六、模式分解（无损分解、保持函数依赖）

规范化通过拆分表（模式分解）消除冗余依赖，两个核心判定标准：

1. **保持函数依赖分解**
    
    拆分后所有原始函数依赖，仍能在拆分后的子表中找到；简易判断：每个依赖 X→Y 的 X、Y 在同一个子表内。
2. **无损分解**
    
    拆分后的子表自然连接，能还原原始完整关系。
    
    - 分解为 2 个子表判定定理：R1∩R2 → R1−R2 或 R1∩R2 → R2−R1；
    - 分解≥3 个子表：使用表格法逐行推导，若最终存在一整行全匹配标记，则无损。
    
3. **反规范化**
    
    牺牲范式、允许数据冗余，减少多表连接查询，提升读性能；代价：数据重复、更新维护复杂、易产生不一致。

## 七、事务、并发控制与三级封锁协议

### 1. 事务四大特性（ACID）

- **原子性 A**：操作要么全执行，要么全部回滚；
- **一致性 C**：事务执行前后数据库数据完整性不变；
- **隔离性 I**：并发事务互不干扰，中间状态对其他事务不可见；
- **持久性 D**：事务提交后修改永久生效，故障不丢失。

### 2. 并发三大问题

1. **丢失更新**：两个事务同时修改同一数据，后提交覆盖先提交结果；
2. **不可重复读**：同一事务两次读取同一数据，中间被其他事务修改，两次结果不一致；
3. **脏读**：事务读取了其他事务未提交、后续回滚的无效数据。

### 3. 三级封锁协议（读锁 S、写锁 X）

1. **一级封锁**：修改数据加 X 锁，事务结束释放；解决**丢失更新**，无法防脏读、不可重复读；
2. **二级封锁**：读数据加 S 锁，读完立即释放；解决丢失更新、脏读，无法防不可重复读；
3. **三级封锁**：读加 S 锁、修改加 X 锁，**全部事务结束才释放锁**；三类并发问题全部解决。

## 八、数据库安全、故障分类与恢复机制

### 1. 数据库安全防护措施

用户身份认证、权限存取控制、密码加密传输、视图权限隔离、全操作审计日志。

### 2. 故障分类与恢复方案

表格

|故障类型|原因|恢复手段|
|---|---|---|
|事务故障|逻辑错误、运算溢出|Undo 日志反向回滚该事务|
|系统故障（宕机）|断电、OS 崩溃|检查点机制，Undo 未提交事务，Redo 已提交事务|
|介质故障（磁盘损坏）|硬盘损坏|装载最新完整备份，Redo 日志重做所有事务|

### 3. 备份策略

1. 静态转储（冷备份）：停机备份，无业务写入，速度快；
2. 动态转储（热备份）：业务运行中同步备份，支持 7×24 可用；
3. 备份类型：完全备份、差量备份（上次全备后变化数据）、增量备份（上次任意备份后变化数据）。

分布式四层架构图

### 1. 四层架构（在集中式三层基础上新增分片、分布层）

从上至下：全局外模式 → 全局概念模式 → **分片模式** → **分布模式** → 局部数据库三层架构；

- 分片模式：全局表拆分为逻辑片段（分片）；
- 分布模式：定义分片存储在哪台节点。

### 2. 分片三种方式

1. 水平分片：按行拆分（条件分片），合并用并运算；
2. 垂直分片：按列拆分，合并用连接运算；
3. 混合分片：水平 + 垂直组合拆分。

### 3. 分布透明性

1. 位置透明：程序无需关心分片物理存放节点；
2. 复制透明：无需感知多副本数据来源；
3. 局部模型透明：不用关心本地数据库是关系 / NoSQL。

### 4. 分布式数据库优点

负载均衡、可平滑扩容、局部故障不影响全局、数据就近访问、可靠性高。

## 十三、NoSQL 非关系数据库

### 1. 四大分类及场景

1. **键值存储**：最简单模型，put/get/del；内存型（Memcached）、持久型（Riak）、混合（Redis）；
2. **文档存储**：JSON/BSON 格式（MongoDB），无需预定义表结构，支持复杂嵌套查询；
3. **列存储**：按列聚合存储，OLAP 海量分析场景，减少 IO 读取；
4. **图存储**：节点 + 关系 + 属性，社交网络、复杂链路分析。

### 2. CAP 理论与 BASE

1. CAP：一致性 Consistency、可用性 Availability、分区容错 Partition Tolerance；分布式系统三者不可同时满足；
    
    - CP：放弃可用性，保证强一致；
    - AP：放弃强一致，保证可用；
    - CA：无分区场景，单机数据库。
    
2. BASE：NoSQL 设计理念，基本可用、柔性状态、**最终一致性**，牺牲实时一致换取高扩展。

### 3. 存储布局

行存储（OLTP 事务系统）、列存储（OLAP 分析）、LSM-Tree（日志型海量写入）。

## 十四、SQL 标准语法

### 1. DDL（定义）

CREATE/ALTER/DROP 表、索引、视图；主键 PRIMARY KEY、外键 FOREIGN KEY。

### 2. DML（查询操作）

标准 SELECT 完整语法：

```sql
SELECT [DISTINCT] 列
FROM 表/视图
WHERE 行筛选条件
GROUP BY 分组列 HAVING 分组后聚合过滤
ORDER BY 排序字段 ASC/DESC
```

配套操作：INSERT、DELETE、UPDATE；模糊匹配 LIKE（% 任意字符、_单个字符）；聚合函数 MAX/MIN/AVG/SUM/COUNT；集合运算 UNION/INTERSECT/MINUS。
