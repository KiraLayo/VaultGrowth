# NoSQL 非关系数据库

> 第二版**新放入**教材（以前是扩展），"现在案例考察的重点"。**NoSQL = Not Only SQL（不仅仅是 SQL）**——不是"非 SQL"（老师专门纠正）。主要应用于大数据处理。

## 四大分类（常考）

| 分类 | 代表 | 要点 |
|------|------|------|
| **文档存储** | MongoDB、CouchDB | JSON/BSON 存数据；无预定义表结构、可复杂查询；缺点：无统一查询语法、无事务 |
| **键值存储** | Memcached、**Redis**（考得多） | put/get/delete；值可任意类型；最简单；临时性（内存）/永久性/两者兼具（Redis 先内存后硬盘） |
| **列存储** | HBase | 按列聚合；适合大数据、数仓、挖掘；可扩展性强 |
| **图存储** | — | 节点+关系+属性；社交网络、知识图谱、规则引擎；复杂性高 |

## CAP 理论（必考，三选二）

- **C 一致性**：所有节点同一时刻数据相同（与 ACID 的 C 同义）
- **A 可用性**：任何请求都有响应
- **P 分区容错**：网络分区/节点故障时系统仍能工作

**三者最多只能满足两个**（"看他要什么和少了什么"，别死记硬背）：

| 组合 | 取舍 | 对应理论 |
|------|------|----------|
| **CP** | 要一致性、放弃可用性 | 考虑 **ACID**（强一致） |
| **AP** | 要可用、放弃强一致 | 考虑 **BASE**（最终一致） |
| **CA** | 去掉了 P（无分区） | 单机数据库，必须完整操作 |

## BASE 理论（必考，ACID 的变种）

**BA 基本可用 + S 软状态（可理解为"无连接"）+ E 最终一致性**——允许数据**一定时间内不同**（大促时"订单数据可能存在错误，10 点后恢复正常"），最终一致。本质：**牺牲一致性换大数据的并发处理与效率**。

## 分区方法（常考）

1. **内存缓存**：高频数据复制到缓存
2. **集群**：多服务器透明提供服务
3. **读写分离（主从复制）**：写服务器慢、读服务器快；案例常考
4. **范围分割（分片）**：请求与更新在同一节点、负载均衡

## 存储布局（常考）

- **行存储**：传统关系型 → **OLTP 联机事务处理**（增删改查日常操作）
- **列存储**：按属性列聚集 → **OLAP 联机分析处理**（数仓/挖掘）；优点：只读少数字段、压缩算法好、局部性群组
- **LSM-Tree（日志结构合并树）**：从**性能角度**入手，解决海量日志记录的索引问题，数据量大、读写效率高

## 常见坑

- NoSQL 全称是 **Not Only SQL**，不是"非 SQL"
- **行存储→OLTP；列存储→OLAP**（老师课上纠正过自己）
- CAP 三选二与 BASE 三要素别搞混："Base 基本可用无连接最终一致性，以及 CAP 三选二"
- Redis：先内存后硬盘（两者兼具）
- MongoDB"严格来说都不能算数据库，只是一个文档"（无事务能力）
