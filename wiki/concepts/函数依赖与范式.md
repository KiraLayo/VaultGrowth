# 函数依赖与范式

> 软考数据库**第一大难点**。考试考选择题："考范式就是这么考，根本就不难做"。

## 函数依赖

- **X→Y**：给定 X 能唯一确定 Y（反向不成立——y=x² 中给定 Y 不能唯一确定 X）
- **部分依赖**：AB→C 且 A→C（AB 的一部分能决定 C）。**只存在于联合（复合）主键**——单属性主键无"部分"可言，必然满足 2NF
- **传递依赖**：A→B、B→C（前提：A 与 B 不等价），则 A→C
- **多值依赖 X→→Y**（两个箭头）：给定 X，一组 Y 值与 Z（=U−X−Y）无关；Z 为空=平凡多值依赖=函数依赖；非平凡才触发 4NF
- Armstrong 公理（自反/增广/传递/合并/伪传递/分解）：不怎么考，了解

## 各类键

| 键 | 定义 |
|----|------|
| 超键 | 能唯一标识的属性集合（**可冗余**） |
| 候选键 | 最小超键（去掉冗余） |
| 主键 | 从候选键中任选一个 |
| 外键 | 其他表的主键 |
| 主属性 | **所有候选键**里的属性（不分情况取并集）；其余为非主属性 |

**求候选键文字法（必考）**：① 从未在依赖集右边出现过的属性必在候选键中；② 由它们按依赖推导其余属性；③ 推不出来就把缺的属性加进来再推；④ 能推出全集的最小集合即候选键（穷举缺口分支）。

## 三大完整性约束

- **实体完整性**：主键非空、不重复
- **参照完整性**：外键要么匹配主表主键，要么为空（外键可以为空！）
- **用户自定义完整性**：业务规则（性别只能男/女、年龄 < 150）

## 范式（层层递进，从底层判断）

| 范式 | 消除什么 | 判定要点 |
|------|----------|----------|
| 1NF | —（默认满足） | 列不可再分，禁止复合属性（家庭地址=复合属性 → 连 1NF 都不是） |
| 2NF | 非主属性对主键的**部分**依赖 | 联合主键中一部分能决定非主属性 → 不是 2NF |
| 3NF | 非主属性对主键的**传递**依赖 | 考得最多 |
| BCNF | 主属性对码的部分/传递依赖 | **每种候选键情况下**，每个依赖左边的决定因素都包含候选键 |
| 4NF | 非平凡**多值**依赖 | 偶尔会考；实际开发很少用 |

- 判定步骤：**先求候选键**（范式题第一步）→ 区分主/非主属性 → 找部分/传递依赖
- BCNF 以上：公司商业数据库一般到 **3NF** 即可，不是越高越好（拆表越多越不利查询）

## 真题演练

> **真题 1（候选键）**：U={A,B,C,D}，F={AB→C, CD→B}。右边出现 B、C → A、D 必在候选键；ABD 由 AB→C 推出 C ✓；ACD 由 CD→B 推出 B ✓ → 候选键 **ABD、ACD**；主属性 A/B/C/D 共 4 个，**非主属性 0 个**。

> **真题 2（范式判定）**：U={E,M,N,L,Q}，F={E→N, EM→Q, M→L}。候选键=EM；E→N、M→L 都是"联合主键的一部分决定非主属性"=部分依赖 → **1NF**，需分解（选 D）。

> **课堂核心实例（教务系统逐步分解）**：学生(学号、姓名、系编号、系主任、课程号、成绩)，联合主键(学号,课程号)。
> 学号→姓名/系编号 是部分依赖 → 拆：学生表(学号,姓名,系编号,系主任) + 选课表(学号,课程号,成绩)；学生表内 学号→系编号→系主任 是传递依赖 → 再拆：学生(学号,姓名,系编号) + 系(系编号,系主任) + 选课 → 三表均 3NF。**"把有依赖的放在一起"**。

> **BCNF 判定**：S、T、J，F={SJ→T, T→J}。候选键有两种情况：ST 与 SJ。情况 1（ST）：SJ→T 含 S ✓、T→J 含 T ✓；情况 2（SJ）：**T→J 左边 T 不含 S/J ✗** → 有一种情况不满足就不是 BCNF（尽管达 3NF）。改 T→J 为 TS→J 后满足。

> **4NF 实例**：telephone(customer_id, phone, cellphone)——phone/cellphone 只允许单值 → 4NF；可多值 → 存在多值依赖、非 4NF；改造为 (customer_id, 电话号码, 电话类型) 恢复 4NF（调查问卷只让填一个固定+一个移动电话就是人为规避多值依赖）。

## 常见坑

- **做范式题必须先求候选键**（否则无从找部分/传递依赖）
- 部分依赖**只存在于联合主键**；单属性主键必然 2NF
- 主属性 = **所有候选键的并集**（ABD、ACD 两种 → A/B/C/D 全主属性）
- 层层递进：不是 2NF 就肯定不是 3NF/BCNF，从底层判断
- 传递依赖前提：A 与 B 不等价（等价就是同一属性，无传递）
- "多种情况"≠"多个属性"：BCNF 要求**每一种候选键情况**都满足
- 键=码（主键=主码），别当成两个概念
- 外键**可以为空**（参照完整性允许）
- 4NF 定义口径：课本=每个非平凡多值依赖 X→→Y 的 X 含候选键；老师通俗=非主属性相互独立、不能取多个值——两者并存
