# 分页存储管理

> **重点考点**：分页真题考得简单，主要考两类——**地址转换**和**页面置换/调度**。

## 引入动机

整存模式下"内存 4GB、程序要 10GB"装不下（游戏普遍 10+GB）。利用**局部性原理**（见 [[wiki/concepts/局部性原理]]）按执行顺序**逐页调入**："执行到哪一页调哪一页"。

## 地址转换（必考计算）

- 逻辑地址 = **页号 + 页内偏移**；物理地址 = **物理块号 + 页内偏移**（偏移不变）
- **页号位数由页的个数决定**（n 页 → log₂n 位）；**页内偏移位数由页大小决定**（页大小 2ᵏ → 偏移 k 位）
- 页表 = 逻辑页号 → 物理块号 的映射
- 16 进制每 1 位 = 4 位二进制（12 位 = 3 个 16 进制位）

```mermaid
flowchart LR
    A["逻辑地址 1D16H<br/>页号 1 | 偏移 D16"] --> B["查页表：页号 1 → 物理块号 3"]
    B --> C["物理地址 = 块号 3 + 偏移 D16"]
    C --> D["3D16H"]
```

**解题四步**：① 定页内偏移位数（页大小决定）→ ② 偏移在低位、页号在高位 → ③ 二进制按位切分 → ④ 页号查页表、偏移不变。"看会了基本上所有题目都会做了。"

- 优点：内存利用率高、碎片极小（**内部碎片只在最后一页**）；缺点：页表增加系统开销、频繁置换引发抖动
- 分页是静态固定分配（页大小提前约定，如 4KB）

## 快表（TLB）

- 页表（慢表）存在内存里，每次查表都访问内存太慢
- **快表 = 小容量高速相联存储器，存页表最常访问项的副本，放在 cache 里**
- 命中快表：1 次 cache + 1 次内存取数；未命中走慢表：2 次内存

## 页表状态位（置换淘汰依据）

| 位 | 含义 |
|----|------|
| 状态位 | 0=不在内存、1=在内存 |
| 访问位 | 0=没访问过、1=访问过 |
| 修改位 | 0=没修改过、1=修改过 |

**淘汰原则（默认按 LRU）**：先看访问位（优先淘汰"最近没被访问"的）；都访问过再看修改位（淘汰"没被修改"的——**不用写回外存，代价最小**）。

## 页面置换算法

| 算法 | 策略 | 评价 |
|------|------|------|
| OPT 最优 | 淘汰**未来最长时间不访问**的页面 | 理论基准，无法实现（"我又不是预言家"），只作衡量 |
| FIFO 先进先出 | 先调入先淘汰 | **会产生抖动**（不利用局部性：分配的物理空间越多缺页率反而越高） |
| LRU 最近最少使用 | 淘汰最近最久未使用页，基于局部性原理 | **考试重点，性能最优，不产生抖动** |
| LFU 最少访问 | 淘汰访问次数最少页 | 了解 |

**抖动（颠簸）**：物理块分配过少引发频繁缺页置换、CPU 利用率暴跌——机制与工作集解法详述见 [[wiki/concepts/虚拟存储]]（FIFO 产生抖动、LRU 不产生）。

## 真题演练

**真题 1：分页地址转换（1D16H）**
> 页面大小 4K，页表：页号 1 → 物理块号 3，逻辑地址 1D16H 的物理地址？

- 答案：**3D16H**。4K=2¹² → 偏移 12 位 = 3 个 16 进制位；低 3 位 **D16 是页内偏移**（不变），高位 **1 是页号** → 查表换 3
- 变种：偏移 10 位、或十进制地址，都先转二进制再取低 N 位

**真题 2：页面置换淘汰（状态位/访问位/修改位）**
> 进程 4 页（0-3），分配 3 个存储块，访问前页 1 不在内存（状态位 0），页 0/2/3 访问位均为 1，页 3 修改位 0，淘汰哪个代价最小？

- 答案：**淘汰页 3**。默认按 LRU；先看访问位（全 1 都访问过）→ 再看修改位：页 3 修改位 0 不用写回 → 代价最小
- 常见坑：淘汰次序"**先访问位、后修改位**"，不能只看修改位
