# 进程管理

## 进程组成

进程 = **PCB（进程控制块，唯一标识）** + **程序段**（描述进程要做什么）+ **运行数据**（存放执行所需数据）。

- PCB 是进程的**唯一标识**：内含进程号等标识信息
- 控制块家族：PCB（进程）/ TCB（线程控制块）/ FCB（文件控制块）

## 进程状态转换（必考·必会画）

![[wiki/assets/进程三态五态转换图.jpeg]]
> 图：进程三态/五态转换图（课件原图）

**三态（考试只考三态）**：

| 状态 | 含义 |
|------|------|
| 运行态 | 正在运行，**需要 CPU** |
| 就绪态 | **除 CPU 外什么都具备了**，在就绪队列等待调度 |
| 阻塞态（等待态） | 既没有 CPU，还缺其他条件（如等待外设数据传输） |

**转换规则（两个单向箭头是考点）**：
- 运行 ↔ 就绪（**双向**）：时间片到 → 就绪；调度选中 → 运行
- 运行 → 阻塞（单向）：运行中等待 I/O/事件（CPU 用中断/DMA 方式处理，不会空等进程）
- 阻塞 → 就绪（单向）：等待事件完成后**只能进就绪队列，不能直接进运行**（CPU 要等调度）
- 就绪 → 阻塞：**不存在**（不在运行就不会遇到等待事件）

**五态（不考，了解）**：新增新建态（创建后尚未分配到就绪队列）、终止态（运行完毕释放资源）。

## 前趋图

反映任务之间的**并行关系 + 先后顺序**。
- 箭头含义：箭头起点执行完后才能执行终点
- 多箭头指向同一节点：所有前驱都执行完才能执行它（如 A/B/C 并行，D 需 ABC 全完成）

常结合 PV 操作出题 → [[wiki/concepts/PV操作与信号量]]。

## 进程资源图（以前常考、近年几乎不考）

![[wiki/assets/进程资源图示例.jpeg]]
> 图：进程资源图示例（课件原图）

- 矩形 = 资源（框内**圆点数 = 资源实例数**），圆形 = 进程
- **资源 → 进程**：资源已分配（指向进程的箭头数 = 进程拥有的资源）
- **进程 → 资源**：进程在申请该资源
- 阻塞节点：申请的某类资源已被分配完、无法获得
- **全部进程都是阻塞节点 → 系统死锁**

**解题技巧**：先释放非阻塞进程的资源（回收），再判断剩余进程是否可运行；循环往复看能否全部执行完。核心：资源分配给进程用完后**会归还/释放，不是消耗掉**；化简时先运行非阻塞节点，可把已执行进程相关的线全部划掉。

## 线程

- 引入目的：进程创建/切换开销大，线程轻量化，提升系统并发度
- 分工：**进程 = 资源分配的独立单位；线程 = CPU 调度执行的最小单位**
- 线程私有：**栈、寄存器、程序计数器**
- 线程共享所属进程的：**代码、全局变量、文件资源**

## 真题演练

**真题 1：三态转换（FCFS 状态题）**
> 单处理机系统，先来先服务调度。P1 运行、P2 就绪、P3 等待打印机、P4 等待扫描仪。问 P1 **时间片到**后各进程状态。

- 答案：**P1 就绪、P2 运行、P3/P4 等待（选 A：时间片到）**
- 思路：运行态只有两条出路——时间片到→就绪，或等待事件→阻塞；选项中无"等待事件"，P1 只能去就绪；FCFS 下 P2（先来）接管 CPU；P3/P4 等外设不变。
- 常见坑：阻塞完成只能进就绪、不能直进运行；就绪进程不会"突发等待"变阻塞。

**真题 2：进程资源图化简**
> 资源分配：R1 两个全分配完、R2 三个全分配完、R3 有剩余；P1 请求 R2、P2 请求 R1、P3 请求 R3。问阻塞节点？能否化简？

- 答案：**P1、P2 是阻塞节点，P3 非阻塞；图可化简，选 B（首个化简进程只能是 P3）**
- 思路：P3 唯一非阻塞 → 先执行，归还其拥有的 R1/R2/R3 各一个 → P1（要 1 个 R2）或 P2（要 1 个 R1）可运行；化简顺序 P3→P1→P2 或 P3→P2→P1
- 常见坑：用排除法——选项含"P3 不是首个"的全错；资源**用完归还**，不是消耗掉
