# LLM Wiki — Schema（中文版）

> ⚠️ 本页是根目录 `CLAUDE.md`（英文原文）的中文翻译，供人阅读。**LLM 运行项目时以英文原版为准**；两者如有出入，以英文原版为准。

## 项目定位

本库是一个**个人成长与学习知识库**，采用 [[wiki/sources/llm-wiki]] 模式。你正在多个领域学习——技术、外语、哲学，以及任何引起兴趣的智识追求。助手的工作是让知识复利：**每次摄入一个来源、回答一个问题，都要让知识库比以前更丰富。**

你不仅是 passively 收集信息，而是在主动构建技能、加深理解、形成自己的观点。知识库应反映这一点：

- **追踪进度**：学了什么、下一步学什么、什么与什么相连
- **浮现连接**：编程概念呼应哲学思想；某个语法点因为另一门语言的概念而豁然开朗
- **支持复习**：页面结构应便于回顾与巩固旧知识
- **向上构建**：基础概念链接到进阶概念；摘要演变为综合

## 目录结构

```
index.md              # 全库主索引（链接 + 一句话摘要）
log.md                # 按时间顺序的追加式活动日志
raw/                  # 原始资料——不可变，LLM 永不修改
  assets/             # 剪藏/导入的原始资料图片
  articles/           # 网络文章、博客、剪藏内容
  books/              # 读书笔记、章节摘要、高亮
  courses/            # 课程材料、讲义、大纲
  other/              # 视频、播客、个人笔记、杂项
wiki/                 # 所有 LLM 生成的内容——你拥有它
  assets/             # wiki 页面专用图片（图表、截图）
  entities/           # "事物"：技术、工具、语言、人物、思想流派
  concepts/           # 思想、理论、原则、词汇、语法点
  skills/             # 实用技巧：技术、工作流、问题解决模式
  sources/            # 已摄入原始资料的摘要页
  syntheses/          # 跨领域分析、对比、学习路线、论述
  journal/            # 定期反思：周回顾、学习里程碑、"啊哈"时刻
```

## 约定

### 页面格式

每个 wiki 页面必须以 YAML frontmatter 开头：

```yaml
---
type: entity | concept | skill | source | synthesis | journal | meta
domain: 技术 | 语言 | 哲学 | 元 | 通用
tags: [tag1, tag2]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: ["[[source-page-name]]"]
summary: "One-line summary"
status: 种子 | 成长中 | 成熟          # 页面发育程度
mastery: 未学 | 学习中 | 已掌握 | 待复习   # 可选；我的掌握程度，与 status 正交
---
```

**status 含义**：
- `种子`（seed）：空壳占位——定义 + 一两个链接，等待填充
- `成长中`（growing）：有实质内容，但还缺连接、例子或深度
- `成熟`（mature）：发展完善——覆盖面广、交叉链接丰富、多来源支撑

**mastery 含义**（可选字段）：
- `mastery` 回答"我掌握得怎么样"，`status` 回答"页面发育得怎么样"——两者正交
- 用于考点、词汇等任何需要记忆追踪的内容。在复习时更新，而非摄入时

### 页面命名

| 类型 | 路径 | 例子 |
|------|------|------|
| 实体 | `wiki/entities/页面名.md` | `wiki/entities/Rust.md` |
| 概念 | `wiki/concepts/页面名.md` | `wiki/concepts/Ownership (Rust).md` |
| 技能 | `wiki/skills/页面名.md` | `wiki/skills/Debugging with strace.md` |
| 来源 | `wiki/sources/页面名.md` | `wiki/sources/Article - Memory Management.md` |
| 综合 | `wiki/syntheses/页面名.md` | `wiki/syntheses/Rust vs Go - Concurrency.md` |
| 日志 | `wiki/journal/YYYY-MM-DD 主题.md` | `wiki/journal/2026-06-12 Weekly review.md` |

所有内部链接使用 Wiki-links；用 `[[文件夹/页面名|显示文字]]` 提高可读性。

### 原始文件命名

| raw/ 位置         | 命名模式                               | 例子                                                  |
| --------------- | ---------------------------------- | --------------------------------------------------- |
| `raw/articles/` | `YYYY-MM-DD 标题.md`                 | `raw/articles/2026-06-12 Async Rust.md`             |
| `raw/books/`    | `作者 - 书名.md` 或 `作者 - 书名 - ChNN.md` | `raw/books/Aurelius - Meditations - Book 2.md`      |
| `raw/courses/`  | `平台 - 课程名.md`                      | `raw/courses/Coursera - Algorithms Part 1.md`       |
| `raw/other/`    | `YYYY-MM-DD 描述.md`                 | `raw/other/2026-06-12 Podcast - Lex on Stoicism.md` |

创建 `wiki/sources/` 摘要页时，命名与原始文件一致（链接更直观）。

课程素材布局：`raw/articles/课程名/第N章/` 按章分目录，课件命名为 `课件总结-第N章.md`。命名一旦确定保持稳定。

### 图片（assets）

- 源图（课件/剪藏）留在 `raw/assets/` 不动。嵌入 wiki 页时复制到 `wiki/assets/` 并取**描述性中文名**（如 `RAID5示意图.jpeg`），用 `![[wiki/assets/文件名]]` 嵌入并加图注：`> 图：xxx（课件原图）`
- 嵌入位置遵循图片在原文中的位置 → 对应知识点/页面
- 来源页维护配图清单（文件 → 内容 → 嵌入页面）
- 考点缺图时：优先内联 mermaid 示意图（Obsidian 原生渲染），不生成图片文件

### 领域专属约定

**技术：**
- 代码块带语言标签：```` ```rust ````
- 引用结论时链接官方文档或规范
- 区分*理解*（概念页）与*实践*（技能页）
- 用具体技术打标签：`#rust`、`#linux`

**语言 / 外语：**
- 词汇进概念页表格：词 | 读音 | 释义 | 例句 | 备注
- 语法点独立概念页，标 JLPT/N 级或 CEFR 级
- 学习技巧进技能页（影子跟读、SRS 设置）
- 按语言打标签：`#japanese`、`#spanish`

**哲学：**
- 按传统/学派打标签：`#stoicism`、`#analytic`、`#buddhism`
- 原著引用：`> 引文` + 来源页引用
- 综合页用于对比传统或追溯思想演化
- 区分*转述*（X 相信什么）与*评价*（你怎么看）

**备考 / Exam prep（如软考）：**
- 课件（课件）为主源；字幕/讲稿为补充——清洗语气词与时间戳，**不为每节视频单独建页**
- 真题/练习通常内嵌于视频课程（教程+练习形式）。摄入时把例题解法提取进概念页「真题演练」块（含答案+常见坑），溯源到课程来源页。无需单独整理考试文件；如将来有独立真题集，放 `raw/exams/`（可选）
- 考点标注：必考 / 常考 / 不考。当前教材版本已删除的内容统一标"已删除，不再考"，便于 lint 识别跨版本矛盾
- 每个章节保留一张学习路线综合页作为**活进度面板**，每次章节摄入后更新

### 链接

- 每个论断溯源到 `[[wiki/sources/...]]`
- **只有来源页引用 `raw/` 路径**——其「原始文件」字段是 raw 文件的唯一引用点。wiki 页面绝不直接嵌入 raw 路径，只能通过 `[[wiki/sources/...]]` 页链接原始内容
- 默认用**短链接** `[[页面名]]`（Obsidian 按文件名解析）；仅当跨类别 basename 重名时用全路径 `[[wiki/entities/页面]]`；index.md 条目保持全路径
- raw 文件改名/移动后：只更新对应的来源页——短链接无需级联。**命名一旦确定保持稳定**：重命名是全库最贵的操作
- **来源冲突**：多来源不一致时（如课件 vs 视频），页面保留两说，用 `> 口径说明` 块分别引用，以教材/真题为准。**标注，不静默二选一**
- 跨领域积极互链——编程概念呼应哲学思想是金子
- 链接前置概念：讲 Rust traits 要链类型系统；讲虚拟式要链直陈式
- 提到某重要事物但没有页面 → **立刻建种子页**

### 索引（index.md）

- 按类别组织，类别内按领域分子节
- 每条：`- [[wiki/entities/页面名]] — 摘要（YYYY-MM-DD, N sources, 🌱/🌿/🌳）`（用全路径避免跨类别重名）
- 🌱 = 种子 · 🌿 = 成长中 · 🌳 = 成熟
- 每次摄入都更新。回答问题前先读它。
- 进度/状态信息**单点维护**（章节学习路线综合页 / 相关实体页）；元页引用这些页面，不复制易变状态

### 日志（log.md）

- 追加式。每条格式：`## [YYYY-MM-DD] {ingest | query | lint | review | journal | init} | 简述`
- 摄入：列出创建/更新的文件与触发的原始资料
- 提问：记录问了什么、输出是否归档为综合页或日志
- 复习：记录进度、洞察、下一步目标

## 操作

> **摄入前确认守则**：每次摄入，先说明范围与粒度——哪些原始文件、大致建多少页、是单源还是章节批次。若用户已明确列出文件并指示摄入，陈述范围后即可执行；若意图不明或请求开放，**必须等用户确认**。绝不一次性摄入整门课程或大批积压文件。

### 摄入单个来源

用户往 `raw/` 丢一个文件并要求摄入时：

1. **读**来源——先文字，再读 `raw/assets/` 中引用的图片
2. **讨论**要点：什么最突出？什么令人意外？与已有知识矛盾还是延伸？想练习什么？
3. **写**来源摘要页到 `wiki/sources/`
4. **更新**来源触及的每个实体/概念/技能页——补充信息、标注矛盾、强化论断
5. **建**重要但没有页面的内容为种子页
6. 值得可视化（图表、对比表）时生成图片存 `wiki/assets/`，用 `![[wiki/assets/filename]]` 嵌入
7. **更新** `index.md`——每个新建或变更的页面
8. **追加** `log.md` 记录

单个来源通常触及 5–15 个 wiki 页面。宁多勿漏。

### 章节级渐进摄入（课程批次）

适用于课程式学习（备考、语言课）——素材逐章到达、学习逐步深入：

1. **先确认范围**——哪一章、哪些文件、批次粒度（见上方守则）
2. **读**：课件为骨架，字幕/讲稿为补充（跳过语气词和时间戳）。**提取视频中内嵌的题目/练习**——教程+练习形式的课程，例题就在视频内容里
3. **讨论**学习导向的要点：新考点、公式变化、与旧章矛盾的论断
4. **只为真正的新概念建种子页。**建页前先对拟建概念名（及可能同义的关键词）做一次全库 grep 查重——命中即**增量合并**：新事实、例子、矛盾都进既有页，绝不建第二页。每节课的例题累积在同一页的「真题演练」块，绝不另开新页
5. **更新**章节学习路线综合页（勾选已完成模块）
6. **更新** `index.md`（仅本次触及的页面）并追加 `log.md`
7. 计算/记忆类页面标记 `mastery: 待复习`
8. **提醒**用户前面章节待复习的内容

### 重摄入（源文件更新）

用户更新了 raw 文件时（如课件补图或修订）：

1. 对比新内容与来源页、受影响的概念页
2. 重写来源页（结构、配图清单、新细节）
3. 新事实/变化**增量合并**进既有页——绝不建重复页
4. 新图片按上方「图片」约定处理
5. 记录剩余缺口（缺图 → mermaid 补画），log 记为 `ingest | 重摄入`

### 回答问题

1. **读** `index.md` 找相关页面
2. **读**这些页面，按需跟随链接；必要时直接读 `raw/` 源
3. **综合**答案并引用（`[[wiki/页面名]]`）
4. **问**用户答案是否归档——综合页、概念页还是日志。要的话写入并更新索引与日志

### 复习（间隔复习）

用户想复习过去所学时：

1. 查 `index.md` 中 `status: 种子` 或 `成长中` 的页面——复习候选
2. 重读页面，向用户提几个探测性问题测试回忆
3. 复习中出现的新洞察更新进页面。合适时晋升 `种子 → 成长中` 或 `成长中 → 成熟`
4. 在 `log.md` 记录复习会话

补充规则：

- 计算类页面（备考）：遮住公式凭记忆重做步骤；绊倒你的点补进页面「常见坑」
- 更新被复习页面的 `mastery`（已掌握 / 待复习）并勾选路线图清单
- 复习会话是晋升 `种子 → 成长中 → 成熟` 的时机

### 日志（Journal）

用户反思学习（周回顾、里程碑、洞察）时：

1. 在 `wiki/journal/` 建带日期和标题的条目
2. 链接最近参与过的相关页面
3. 记录什么有效、什么无效、要调整什么
4. 这是用户的空间——他们的声音和视角优先。助手负责结构化与连接，不代写内容

### 体检（Lint）

定期健康检查，查找：

- **矛盾**：两个页面论断互斥
- **过时论断**：被新来源取代的断言
- **孤儿页**：没有入链的页面
- **缺页**：提到的重要概念/实体没有自己的页面
- **种子债**：太多从未发展的种子页
- **跨领域机会**：一个领域的概念与另一领域呼应但未链接
- **知识空白**：明显关心却尚未有来源的话题
- **重复概念**：两个页面描述同一概念——合并候选
- **跨版本矛盾**：标"已删除/不再考"的论断与新来源冲突
- **摄入卫生**：近期新建的页面本应合并进既有页
- **断裂链接**：所有 wikilink、raw 引用、图片嵌入的目标必须存在（raw 移动/改名会静默断掉来源页引用）
- **来源页一致性**：每个来源页的「原始文件」链接与实际 raw 文件路径/名称一致
- **元页漂移**：元页（使用指南、实体页）中的进度/状态描述与现状一致
- **frontmatter 有效性**：YAML 必须可解析——引号配对、日期 YYYY-MM-DD、无重复键、流式数组内不得含 `#`（`tags: [a, #b]` 会让括号永不闭合——frontmatter 标签不写 `#` 前缀）

报告发现并修复。记录做了什么。
